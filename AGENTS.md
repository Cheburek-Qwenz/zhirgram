# AGENTS.md: ZhirGram (клиент Telegram на Compose + TDLib)

Файл для агента, который продолжает работу над проектом. Прочитай целиком до первой правки.

## Что это и для кого

Собственный Android-клиент Telegram. Рабочее название ZhirGram, пакет `com.qwenz.zhirgram`
(переименование разрешено, см. «Юридическое»). Владелец говорит по-русски: отвечай по-русски,
коротко, без воды. Он делает моды и приложения на Compose (Kotlin), собирает на телефоне
(Termux, CodeAssist), поэтому **тяжёлая сборка идёт только в GitHub Actions**.

Цели:
1. Настоящий Material 3 и Material 3 Expressive (пружинные анимации, формы, морфинг), без имитации.
2. Переключатель стиля: Expressive / Material 3 (уже есть в `UiStyle`).
3. Позже: переключатель «Классический интерфейс» (старый вид). Это отдельная работа, см. этап 5.

## Архитектура

- **TDLib, а не форк DrKLO/Telegram.** Клиент написан с нуля на Compose, сеть и хранилище делает TDLib.
- `td/TdRepository.kt`: единственная точка контакта с TDLib. Принимает `TdApi.Object` из потока TDLib,
  отдаёт `StateFlow` (`auth`, `chats`) и `SharedFlow` ошибок. UI про `TdApi` ничего не знает,
  UI видит только свои модели (`AuthState`, `ChatItem`). Держи это разделение.
- `data/Settings.kt`: DataStore (стиль интерфейса, динамические цвета).
- `ui/theme/Theme.kt`: `MaterialExpressiveTheme`, `MotionScheme.expressive()` или `.standard()`,
  `LocalUiStyle`. Компоненты читают `LocalUiStyle`, чтобы выбрать Expressive- или обычный вариант.
- `ui/components/Components.kt`: `springPress`, `pressCorner`, `ZhirButton`, `ChatAvatar`.
- `ui/Root.kt`: корень, оболочка с вкладками, навигация состоянием (без navigation-библиотеки, пока
  экранов мало; когда появится экран чата, подумай про `navigation3` или свой стек).
- `org.drinkless.tdlib.*` (`Client`, `TdApi`) и `libtdjni.so` **в git нет**: их создаёт
  `.github/workflows/build-tdlib.yml` и кладёт в Release `tdlib-latest`. `build-apk.yml` скачивает.

## Честный статус (на момент создания)

**Ничего не компилировалось и не запускалось.** У автора заготовки не было сети для Gradle и
TDLib. Проверено только чтением. Первый CI-прогон почти наверняка потребует правок. Вероятные места:

- `gradle/libs.versions.toml`: AGP 9.5.1, Kotlin 2.4.21, BOM 2026.09.00 сверены с документацией 17.11.2026
  (первоначальные версии из памяти не подошли и были заменены). activity, lifecycle, datastore, core-ktx
  всё ещё из памяти, при ошибках обновляй. `material3 = 1.5.0-rc01` взята со страницы релизов
  (RC от 4 ноя 2026). Если вышла 1.5.0 stable, обнови. Версию Gradle в `build-apk.yml` держи
  совместимой с AGP.
- Expressive API в 1.5.x: проверь по KDoc той версии, что есть и как называется.
  Использованы: `MaterialExpressiveTheme`, `MotionScheme.expressive()/standard()`,
  `ButtonDefaults.shapes()`, `ToggleButton` + `ToggleButtonDefaults.shapes()`, `LoadingIndicator`,
  `MaterialShapes.*` + `toShape()`, `ShortNavigationBar(Item)`, `motionScheme.defaultSpatialSpec()` и т.д.
  Если чего-то нет, используй fallback из `.claude/skills/material-3-expressive/references/code-patterns.md`
  и оставь комментарий, какой Expressive-компонент заменён.
- `build-tdlib.yml`: аргументы `build-openssl.sh` / `build-tdlib.sh` сверены только с README, не с самими
  скриптами. Первый запуск, скорее всего, придётся поправить. Скрипты собирают все ABI, это долго
  (десятки минут), но выполняется один раз.
- `TdRepository.kt` написан против Java-API TDLib: имена классов и полей (`TdApi.SetTdlibParameters`,
  `UpdateChatPosition`, `ChatPosition.order` и т.д.) проверь по сгенерированному `TdApi.java`
  выбранного коммита. Поля в Java публичные, поэтому конструкторы с аргументами не используются,
  только `apply { поле = значение }`.

Когда отчитываешься о работе, говори **что именно проверено**: «прочитал», «собралось в CI»,
«запускал на устройстве». Не пиши больше, чем проверил.

## Правила дизайна (обязательно)

Скиллы лежат в `.claude/skills/material-3` и `.claude/skills/material-3-expressive`. Прочитай их `SKILL.md`
и нужные `references/`.

- Настоящие Material-компоненты с поднятым состоянием. Никаких «коробок по смещениям».
- Цвета только из `MaterialTheme.colorScheme` с парными `on*`. В компонентах нет hex.
- Движение, размер и форма: **spatial-пружины** из `MaterialTheme.motionScheme` (могут отскакивать).
  Цвет и прозрачность: **effects-пружины** (без отскока). Не хардкодить `spring(...)`/`tween(...)`
  в экранах, брать из темы, чтобы стиль переключался во всём приложении.
- Нажатие, выбор и включение меняют форму там, где компонент это умеет.
- Один главный action на экран, крупнее остальных. Подписи у навигации оставлять.
- Касания не меньше 48dp, `contentDescription` у иконок-кнопок, цвет не единственный сигнал.
- Уважать системное «убрать анимации» (TODO: сейчас не сделано, см. этап 8).
- Режим `MATERIAL3` должен ощущаться спокойным: стандартные пружины, постоянные формы.
  Режим `EXPRESSIVE` должен ощущаться живым. Любой новый компонент проверь в обоих режимах.
- API-имена не выдумывать. Сомневаешься: открой KDoc версии из `libs.versions.toml`.

## Правила TDLib

- Все обновления обрабатываются в `TdRepository.onUpdate`. Не создавай второй `Client`.
- Обработчики результатов вызываются в потоке TDLib. Не трогай UI оттуда, меняй только `StateFlow`.
- Не блокируй поток обработчика долгой работой.
- Ключ шифрования базы сейчас пустой. Для публикации сделай его из Android Keystore.
- Не логируй номера, коды, пароли, тексты сообщений.
- Бинарники TDLib из чужих репозиториев не использовать: библиотека видит весь трафик и токены.
  Собирай сам workflow'ом.
- `proguard-rules.pro` держит `org.drinkless.tdlib.**`. Не убирай. `build-apk.yml` проверяет это после сборки.

## Секреты

`TG_APP_ID`, `TG_APP_HASH`, ключ подписи берутся из `local.properties` (локально, в .gitignore) или из
Secrets репозитория (CI). **Никогда не коммить** `api_id`, `api_hash`, `.jks`, пароли. Перед каждым коммитом
`grep` по этим значениям. Токены и пароли не передавай в аргументах команд и не печатай в логи CI.

## План работ

Делай по порядку. Каждый этап заканчивай рабочей сборкой в CI.

0. **Первая сборка в CI.** Запустить `Build TDLib`, потом `Build APK`. Исправлять версии и API,
   пока не соберётся. Зафиксировать коммит TDLib. Добавить gradle wrapper.
1. **Вход.** Номер, код, облачный пароль уже есть. Добавить: повторная отправка кода, таймер, выбор страны
   и маска номера, ошибки по-русски (`PHONE_NUMBER_INVALID` и т.д.), вход по QR, регистрация нового аккаунта.
2. **Список чатов.** Есть: сортировка, превью, время, непрочитанные, анимация перемещения.
   Добавить: фото чатов (`UpdateChatPhoto` + `DownloadFile`, морф формы аватара при нажатии), закреплённые,
   mute, статус отправки и доставки, папки и архив (`ChatListFolder`, `ChatListArchive`), поиск
   (`SearchBar` / `AppBarWithSearch`), подгрузка (`LoadChats` постранично), `FloatingActionButton` или
   `FloatingActionButtonMenu` для нового чата.
3. **Экран чата.** Сообщения (`GetChatHistory`, обновления `UpdateNewMessage`, `UpdateMessageContent`),
   пузыри с Expressive-формами, ввод и отправка (`SendMessage`), ответы, редактирование, удаление,
   фото и файлы, голосовые, стикеры, форматирование. Пересылка, реакции, ссылки.
4. **Настройки.** Профиль, уведомления, конфиденциальность, хранилище, язык, темы с seed-цветом.
5. **Классический интерфейс.** Отдельный набор экранов (список чатов, чат) со старой компоновкой, а не
   просто другая тема. Заготовка: ввести `enum UiStyle { …, CLASSIC }` и интерфейс оболочки,
   за которым прячутся две реализации. Общими остаются `TdRepository` и модели. Сначала согласуй
   с владельцем, как именно должен выглядеть «старый интерфейс».
6. **Уведомления.** Без своего Firebase-проекта пуши в закрытом приложении не приходят. Варианты:
   свой FCM-проект и `RegisterDevice`, либо foreground-сервис / UnifiedPush. Обсудить с владельцем.
7. **Обновления и релизы.** Теги `v*` публикуют APK в Releases (workflow готов). Решить, нужна ли
   проверка обновлений внутри приложения.
8. **Доступность и качество.** Reduced motion, большие шрифты, TalkBack, превью `@Preview` (светлая и
   тёмная тема, большой шрифт), тесты репозитория на фейковых `TdApi`-обновлениях.

## Юридическое

- TDLib распространяется под Boost Software License 1.0 (разрешающая). Её текст нужно сохранить
  при распространении.
- Свой `api_id` и `api_hash` с my.telegram.org обязателен. Чужие ключи не использовать.
- Перед публикацией прочитай API Terms of Service Telegram (core.telegram.org/api/terms) и
  требования к неофициальным клиентам. Не называй приложение «Telegram» и не используй его логотип
  и иконку. Не выдавай клиент за официальный.
- Проект не форк DrKLO/Telegram, поэтому GPL на него сама по себе не распространяется. Если когда-нибудь
  возьмёшь код из GPL-проектов (в том числе из MargyGram), весь проект станет GPL и исходники придётся
  открыть.

## Как работать

- Не раздувай. Делай минимум, что просит этап, остальное пиши в TODO.
- Перед коммитом: нет ли секретов, собирается ли в CI, оба режима стиля работают.
- Если не уверен в решении, которое нельзя легко откатить (формат хранения, схема подписи, имя пакета),
  спроси владельца, а не угадывай.
